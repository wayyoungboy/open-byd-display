OpenBYDDisplay

比亚迪仪表显示与车机互联开源项目。从车机客户端、连接协议到自研仪表服务，逐步构建可研究、可验证的开放实现。无需登录、VIP 或商业许可证。 Open-source instrument-cluster display and head-unit connectivity for BYD vehicles. From the head-unit client and wire protocol to a self-developed cluster service — an open, verifiable implementation built step by step. No login, VIP tier or commercial license.

无账号 / 无授权门槛No login, no paywall

无需登录、VIP 或商业许可证。线路编码器会拒绝发送 token / client_time 字段。No login, VIP tier, commercial license or token. The wire encoder refuses to send token / client_time fields.

USB NCM 传输USB NCM transport

基于 TCP 的换行分隔 JSON。车机 NCM 地址 192.168.77.2，仪表默认 192.168.77.1。App 不自行配置 NCM 接口。Newline-delimited JSON over TCP. Head unit binds 192.168.77.2; cluster default 192.168.77.1. The app does not configure the NCM interface itself.

更新包本地预检Local package pre-check

ZIP 固件包：六个必需文件、路径净化、ZIP CRC 与各 SV 压缩体 MD5；FUP2 组件包：头、清单、路径与逐文件 SHA-256。ZIP firmware: the six required files, path sanitisation, ZIP CRC and each SV body MD5. FUP2 package: header, manifest, paths and per-file SHA-256.

安全默认的任务处理Safe-by-default jobs

上传与安装为两个独立、需显式确认的动作；任务状态持久化，结果不明时只查询、不自动重试。Upload and install are separate explicit actions; job state is persisted, uncertain results are only queried and never auto-resubmitted.

自研投屏链路 (0.1.2)Self-developed cast link (0.1.2)

MediaProjection → H.264 → BVL1/LHF2 发送；按屏幕面积选投屏 profile；歌词 / 导航叠加协议与实验服务。MediaProjection → H.264 → BVL1/LHF2 sender; area-based cast profile selection; lyrics / navigation overlay protocols with a lab service.

原生视频核心Native video core

C99 BVL1/LHF2 回环接收、帧校验及真实 H.264 解码实验；Clang/LLD 无 SDK 生成 ARM32 探针与播放器（待 QNX 运行验证）。C99 BVL1/LHF2 loopback receive, frame validation and real H.264 decode tests; Clang/LLD builds ARM32 probes and a player without an SDK (QNX runtime unverified).

自研实验服务Host lab service

仅监听 127.0.0.1、操作沙箱目录的 Python 更新服务参考实现：Ed25519 验签、目标与硬件 ID 绑定、降级拒绝、原子发布。A Python reference service bound to 127.0.0.1 on a sandbox: Ed25519 verification, target/hardware-ID binding, downgrade refusal and atomic publishing.

开机自启与 ADB 辅助Boot startup & ADB helper

默认关闭的开机自启（不恢复上传、不安装、不投屏）；只读权限 / IPv4 诊断，显式配置后台打开权限。Opt-in boot startup (never resumes uploads, installs or casting); read-only permission / IPv4 diagnostics with explicit overlay configuration.

增量安装实验Incremental install

签名差量、基线绑定、完整代际重建、试启动确认及未确认回退。Signed deltas, baseline binding, full-generation rebuild, trial-start confirmation and unconfirmed rollback.

快速开始 / 构建Get started / Build

安装测试版Install a test build

  1. 从 Releases 下载标明测试状态的 APK，对照公布的 SHA-256 校验。Download the APK marked as a test build from Releases and check it against the published SHA-256.
  2. 在车机上旁加载安装（sideload / adb install）。包名 org.openbyddisplay，可与小灰灰并存。Sideload it on the head unit (adb install). Package org.openbyddisplay installs alongside the original app.
  3. 车辆静止、供电稳定时连接车机，先检查、再上传、最后手动确认安装。With the vehicle stationary and power stable, check first, upload, then confirm install manually.

从源码构建Build from source

需要 JDK 17、Android SDK 34 / Build-Tools 34.0.0、Python 3.12。配置好 headunit/local.properties 与虚拟环境后：Requires JDK 17, Android SDK 34 / Build-Tools 34.0.0, Python 3.12. After setting up headunit/local.properties and a venv:

python3 -m pip install -r firmware/requirements.txt
python3 -m unittest discover -s headunit/tools/tests -v
PYTHONPATH=firmware python3 -m unittest discover \
  -s firmware/tests -v
./headunit/gradlew -p headunit :app:testDebugUnitTest \
  :app:lintDebug :app:assembleDebug

现阶段通过 GitHub 下载并选择本地文件，不执行无人确认的固件 OTA。电脑实验包不可刷入现成仪表；旧 App 请保留。更多见仓库 README 与 docs/。 For now packages are downloaded via GitHub and picked as local files; there is no unattended OTA. Lab packages must never be used on a real cluster; keep the original app. See the repository README and docs/.
