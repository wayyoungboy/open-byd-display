# 氛围灯实现与接机验证

本功能在车机端通过真实、已授权 ADB shell 调用车辆接口，与 QNX 仪表接收服务分开。独立实现基于本项目维护者的小灰灰 MIT 代码，版权见 NOTICE。不会调用其他应用 Binder、复用其权限或设备业务凭证。

## 软件模式

- 普通接口为设备 1023 的完整 `[色号, 原始亮度, 区域, 来源]`，通过当前系统反射得到字段；缺字段、重复 ID 或无效读回时拒绝启动。有效色号 1～31，原始亮度 1～6；界面逻辑 0～5 只是减一后的编号，最低档不等于关闭总开关。没有连续 RGB 或更细亮度。
- 动态多色每色先逐档变亮/变暗，再在最暗档换色。等待当前帧确认后开始每档停留，不追赶时钟跳档。
- 默认从播放混音取得 packed FFT，按采样率与真实 FFT 大小分成 16 个频带；忽略 DC/Nyquist，分辨率不足的低频带保持零。通过低频能量、正向频谱变化、时间包络与节拍间隔驱动软件色号/亮度。
- FFT 不可用时明确显示 RMS 回退。麦克风仅在用户手选并授权后使用，目前为 RMS 备选；不会静默切换到麦克风。音频只在内存分析，不录文件或上传。
- 音频工作者只保存一份最新不可变采样，控制端每次发送一个请求并等待对应序号和实际反馈后才继续。重复帧仅 KEEP 续租；普通音乐灯光目标周期 350ms，慢反馈自然降低频率，不积压旧命令。

## 所有权与恢复

控制器先保存前后颜色、亮度和区域；每次写前检查仍拥有当前状态，每帧等待真实前后反馈。写返回失败也可能部分生效，因此先记录待确认目标，再发送；异常后根据实际读回恢复。部分 CAN 反馈允许旧值/目标值的组合，其他变化视为手动调整，让出控制并保留新设置。相同数值的手动操作无法仅靠轮询识别。

STOP 等待恢复结果，原前后值不同时分区恢复，最后恢复区域。单控制器文件锁、loopback 随机端口、会话 token 与递增序号保护独立会话。整行读取有字节上限和绝对期限；EOF 或 3.5 秒没有完整有效续租会尝试恢复。车辆库内部调用可能阻塞，租约不是整个 OEM 调用的硬截止保证。

App 在授予控制前保存 pending 记录。未收到确切 RESTORED/OVERRIDDEN 时，重启 App 仍阻止新控制；人工核对入口要求先停止、等待至少一分钟并在实车检查，明确不算自动读回。真实已授权 shell UID 必须为 2000；授权 ADB 握手成功不等于车辆控制成功。

## 原生后端

实验适配器支持设备 1002 的工作模式/启停与 16 路、每路 0～15 的频谱，要求可读的原始音频状态和完整频谱以确认和恢复。没有字段 ID 猜测或 fallback 数值。

**运行时已验证 profile 列表为空，原生开关关闭且不可用。** Service 与车辆适配器两处检查精确平台 profile，Intent/偏好不能开启。不能以字段存在、用户勾选或车型名称代替实车验证。离线 fixture 只证明控制器的顺序/读回/恢复逻辑。

增加 profile 前必须验证：本机字段映射、完整音频反馈、启停时序、原车优先、频谱是否写回、动画是否改变普通灯光反馈、手动让权与异常恢复。当前契约要求灯光反馈不随音频动画自行漂移；若实测不满足，先实现可验证的所有权模型，再启用。不能因返回码为零宣称原生灯效可用。

## 离线与实车状态

离线测试覆盖 FFT 频率/单位、有符号复数、静音与瞬态、谱值边界和不可变快照；覆盖原有动态周期、RMS、节拍与六档限制；通过假车辆反馈和真实主机 TCP 测试部分写入、读回超时、分区恢复、手动调整、重复序号、EOF 和租约超时。没有运行原应用、发送车辆命令或刷写分区。

待接机逐项记录车型/硬件、APK 摘要、系统版本和原状态：

1. 授权本应用独立 ADB 密钥，验证真实 shell UID、字段与原状态只读。
2. 普通灯光逐档写入并读回；核对六档编号、前后分区和原区域恢复。
3. 检查实际播放软件是否进入混音、FFT/静音/RMS 回退及显式麦克风。
4. 验证视觉节拍同步、慢反馈不排队、切色与亮度限制。
5. STOP、通知停止、反复启停、页面旋转/退出、进程结束、连接断开与失去音源。
6. 原车手动调整优先，原前后值不同也能恢复；恢复不明时阻塞重新启动。
7. 两车型分别完成；原生后端另行按上节验证，保持关闭直到验收。

本项目氛围灯尚未完成实车验收。更多功能与发布状态见[迁移清单](feature-migration.md)。
