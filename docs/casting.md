# 车机投屏与仪表接收

当前为开发版本。以下描述源码能力；未完成 Android 车机、真实 QNX 或仪表目视验收，不作为可刷固件发布。App 只连接宣告 `openbyddisplay.video` / wire_version=1 的自研接收器。不能据此连接采用其他设备授权或 HMI 协议的现成固件。

## 已接入的功能

| 功能 | 行为与边界 |
| --- | --- |
| 屏幕镜像 | 本次用户同意后取得 MediaProjection；回调处理撤销；不保存授权或开机自动恢复录屏 |
| 地图独立副屏 | OWN_CONTENT_ONLY 独立虚拟屏，按指定包名启动地图；系统禁止跨屏启动时提供明确副屏 ID 和 ADB 命令 |
| 高德飞屏版副地图 | 独立 Presentation 屏，名称可配置；地图主 Activity 留在 display 0，由支持该方式的地图版本绑定副地图。副地图绑定与像素仍需真机核对 |
| 动态标定图 | 自研移动图案，可独立检查编码、接收与显示链路，不依赖地图授权或屏幕录制 |
| 窗口布局 | 先读接收器标定矩形，再选区域、居中或小窗；保持画面比例，仅能缩小/移动至允许范围内，不回退固定车型坐标 |
| 画质 | 5～30 fps、0.5～8 Mbps；基线 AVC；可选 2 倍绘制后缩小、左右翻转、窗口不透明度和程序生成的柔边；深/浅随实际车机主题更新 |
| 音乐与歌词 | 用户开启通知使用权后读取活跃播放会话；导入最多 256 KiB 的本地 UTF-8 LRC，文件名与当前歌曲标题一致才显示；不自动联网搜歌 |
| 导航文字 | 仅在开启后接收支持的高德导航广播；结束/到达立即清除，15 秒未更新过期；不会发送固定实验路段 |
| 持续连接 | 连续帧无 60 帧上限；逐帧 ACK/序号核对，CRC、参数集和关键帧校验；空闲心跳，读写事务有期限 |
| 连接恢复 | 最多连续 3 次重试；保留本次编码源、请求新 IDR；不复用 MediaProjection 授权重新建屏。停止/撤权/初始化失败统一释放本次资源 |
| 更新互斥 | 本进程投屏与更新操作互斥；存在未结束更新任务时不允许开始投屏；发送视频握手前持久记录清理状态，丢失清理回执后阻止更新，即使重连完成也不自动抹去旧的不确定结果。恢复入口要求人工确认仪表已恢复，并明确标为人工证据；本机GL清理未确认时先结束并重启App。远端仍需自己的真实互斥与恢复实现 |

歌词、导航文字和柔边由车机合入编码视频。它们不是独立的 QNX 透明叠加层；关闭视频后不能单独显示。柔边深色为黑、浅色为浅灰，不代表仪表下层原车元素会透出；车机与仪表主题是否一致也需核对。权限、地图副屏和 GPU 合成尚未在实际 Android 设备验证。

## 接收协议

手动开发启动 `--serve` 后保持同一监听 socket，串行接受连接。具体参数见[原生媒体](native-media.md)。每个视频会话使用独立窗口组、解码 context 及状态；连接关闭后清理，清理返回失败时停止接纳新会话。

- 只读探测：发送四字节 `INFO`，返回 JSON 行；不打开媒体 context。报告版本、边界和未实现能力。
- 视频握手：`BVL1`、BE u32 JSON 长度 15、精确 `{"op":"stream"}`、四个 BE u32（宽/高/fps/0）。ready 必须明确 `ok=true,ready=true,protocol=LHF2,continuous=true`。
- 窗口：`CONF` 后跟六个 BE u32：cookie、x、y、width、height、opacity。只接受启动时操作者标定的矩形内部配置。`configured` 表示参数被接受，`property_readback` 单独表示窗口回读。
- 空闲：`PING` + BE u32 cookie；回复必须带相同 heartbeat cookie，不改变视频序号。
- 视频：原生 LHF2 24 字节头 + 完整 Annex-B AU，2 MiB 上限；逐帧读取 `ack/accepted_sequence/submitted`，不堆积未读回执。
- 结束：显式 LHF2 EOS，读取 done/cleanup。EOF、丢失回复或错误不等于清理已确认。ACK、Screen POST、属性回读和实际画面分别记录。

`--tcp` / stdin 保留最多 60 帧、30 秒的短测试行为；App 使用持续 `--serve` 模式。`CONF/PING/INFO` 是本项目自己的扩展，不声称其他接收器支持它们。没有商业鉴权层；包签名、载荷摘要与车型检查另行保留。

## 尚未完成

- OEM HMI 主题/页面/中心区域事务、信息页锁定、开始与停止布局确认，以及异常退出恢复。
- 独立透明导航/歌词图层、真正透明/自定义 PNG 遮罩、背景/主题/壁纸编辑及资源更新确认。
- 仪表端 USB 角色后端：车机端已迁移独立 USB/NCM helper，但仍需匹配仪表实现和实车验证；只用接口存在或命令受理不能证明自研仪表已完成切换。
- 自研原生安装后端、开机服务管理、硬件身份与恢复入口、分车型可刷包。
- App 录屏/GL/地图 Presentation 的设备测试、真实 QNX 加载/解码/窗口测试、USB 拔线/重启/警告优先验证。

## 已有离线验证

Kotlin 发送端通过真实 TCP 连接同一份 C stream/media 引擎，发送 70 帧真实 AVC，完成能力探测、配置、心跳、逐帧 ACK 和 EOS；提交数据经 FFmpeg 解码后逐帧摘要一致。QNX 服务调用使用显式 ABI 替身，不是 QNX 执行或实物出画。C 测试另覆盖错误 CRC、范围越界、断线后新首帧、失败清理以及监听 socket 重复接纳连接。

运行 Kotlin 测试需要 C 编译器和带 libx264 的 FFmpeg；CI 明确安装这些工具。参考 Android [MediaProjection 资源恢复](https://developer.android.com/media/grow/media-projection#resource_recovery)；对应原生平台约束见[QNX 构建](qnx66-open-toolchain.md)。
