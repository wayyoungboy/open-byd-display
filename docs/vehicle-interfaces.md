# 车机车辆接口

独立代码在 `headunit/app/src/main/java/org/openbyddisplay/vehicle/`。与 QNX 仪表显示代码分开，通过本应用生成的传统本机 ADB 密钥与系统授权执行；不请求其他应用替代执行。只连接 127.0.0.1:5555，不启动 adbd、不实现无线配对/TLS；UI 显式授权才提交公钥，普通执行不会自动弹授权或重复执行。

## USB 与 NCM

车机 helper 经真实 shell UID 2000 调用仪表设备接口；要求用户停车并核对固件支持。投屏命令受理后等待唯一匹配的 NCM 网卡，配置 192.168.77.2/30；连续两次读回启用和地址才报告配置完成。多候选、已有其他 IPv4、无正确驱动时拒绝猜测。不能用 TCP 可达代替驱动或自研协议身份。

U 盘请求等待稳定期后核对旧接口身份是否真的消失。只清除 IP 不算接口断开；没有明确证据则只报告 COMMAND_ACCEPTED。即使原 NCM 消失也要求在仪表确认实际 U 盘模式。

App 先保存请求 ID，再启动独立 helper；逐次轮询专属结果文件。文件未完整、请求/命令/UID 不符、写后失败或只有命令受理，都保留未知记录。刷新只读原文件，不重新发送模式命令；未知期间禁止新切换、投屏和更新。结果先落本机终态，再清理证据文件，避免清理后丢失终态。

写前失败与写后失败分别标记；只在写前即失败且完整匹配本次请求时自动解除。进程锁由完整作业生命周期 holder 持有并在真正 finally 释放，防止旧 detached helper 与新请求重叠。人工解除需等待至少90秒、由已授权 shell 证明旧 helper 不再持锁，并由用户核对实车模式稳定；明确属于人工证据，不冒充自动回读。

USB 请求与投屏/更新共用进程所有权，持久未知记录跨 App 重启生效。该车机侧实现不补足自研仪表端 USB 角色控制；后者仍待平台适配。当前本项目未做实车往返测试。

## 深浅设置与大灯联动

原生入口解锁只写 `content://carsettings/global` 的 `support_change_system_uimode=1` 并读回。不会写 `sys_screen_mode` 或改成 App 自有的昼夜轮询；原生选项仍由原车设置控制。

联动默认关闭；用户开启后，只有原生和 Android 设置均 Auto，且实际近光信号连续稳定，才临时设置系统 Auto 的实际深/浅效果。原生或 Android 手动选择优先。每次切换读回确认，停止/EOF/租约到期尝试恢复当前自然日出日落 Auto；只恢复仍属于本控制器的状态，不覆盖已改变的手动选择。

未收到确切停止恢复回执时持久阻止重启联动。人工解除要求停止并等待后核对原车设置和主题。主动开启的“保持原生入口解锁”和“大灯联动”才会在启动/用户解锁时尝试恢复；不开启投屏、USB 切换、氛围灯或安装。系统拒绝后台服务及原生状态读不到时不宣称成功。

目前离线覆盖模式/实际近光策略、手动优先、自然 Auto 解析和支持位写入证据；本项目包的真实 Provider/Binder、重启恢复及近光响应仍待车机验证。不要同时运行其他系统模式控制器。

## 实车回归

- 分别核对 USB 两方向、网卡延迟、同接口丢地址、多候选、请求中断、写后失败与人工恢复流程。
- 在投屏和更新中尝试切换必须拒绝；未知 USB 状态下重启 App 仍必须阻止投屏/更新。
- 分别核对原生/Android Auto、固定深色/浅色，近光开关、短暂无效信号、手动优先和停止/拔线后的自然 Auto。
- 核对开机恢复两个选项首次均关闭；开启后真实重启、用户解锁、撤销 ADB 授权和厂商后台限制。
- 小灰灰旧包历史记录不作为新包已经实车通过的证据，参见[迁移状态](feature-migration.md)。
